Recovery requests and existing-account email OTP requests share the same `RecoveryToken`, send timestamp, and cooldown: a new successful request replaces the previous pending code, and verification consumes it. Use the latest reset code, keep sends explicit, and respect the existing sixty-second resend interval and server rate limits.

The server also treats `otp` authentication as recovery for the current-password exemption, so an enabled current-password requirement does not require the forgotten password in this flow.
